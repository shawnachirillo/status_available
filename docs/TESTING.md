# Testing

Use Node from [.nvmrc](../.nvmrc), npm with the checked-in lockfile, PostgreSQL 17 server and client binaries, and curl. Run as a non-root user on Linux or macOS.

```sh
npm ci --no-audit --no-fund
npm run test:unit
STATUS_TEST_PG_BIN=/path/to/postgresql/17/bin npm test
```

The binary override is optional when `pg_config --bindir` already points to PostgreSQL 17. On the original macOS installation the path is `/Library/PostgreSQL/17/bin`. A Homebrew alternative is `$(brew --prefix postgresql@17)/bin`.

## What the commands verify

| Command | Coverage | Infrastructure |
| --- | --- | --- |
| `npm run test:unit` | 43 editor, publication UI and hostname tests | Node only |
| `npm test` | Production build, independent TypeScript check and all 77 tracked regressions | Local PostgreSQL 17 subprocess, private Unix socket, loopback Next.js server and curl |
| Separate staging acceptance | Real Clerk sign-in, Stripe test-mode checkout and webhook delivery, hosted Supabase runtime role and edge routing | Approved staging accounts and isolated credentials |

The runner copies current source into a private temporary directory, builds with a synthetic Clerk public key, initializes an empty PostgreSQL cluster, applies tracked migrations in filename order, and inserts synthetic fixtures. There is no TCP database listener. The runner verifies the runtime identity, hosting functions, fixture and execution grants before it starts a loopback server on an available port. Vitest runs the stateful suites serially within each run. Independent runner invocations use separate databases and HTTP ports. Normal exit and handled interrupts stop the server and database and remove temporary files.

The runner requires no deployed app or external service after dependencies are installed. It invokes only tracked fixtures and suites. Keep the untracked legacy scripts outside CI. GitHub verification probes the same command after npm and PostgreSQL installation.

## Configuration

| Variable | Purpose |
| --- | --- |
| `STATUS_TEST_PG_BIN` | Optional parent-process path to the PostgreSQL 17 bin directory |
| `STATUS_INTEGRATION_TEST_MODE` | Runner sets `true` in the test and server child environments |
| `STATUS_TEST_DB_SOCKET` | Runner-generated private socket directory |
| `STATUS_TEST_DB_PORT`, `STATUS_TEST_DB_NAME` | Internal values `55432` and `status_payment_concurrency_test`. The port is a Unix socket suffix. |
| `STATUS_TEST_HTTP_PORT` | Runner-selected IPv4 loopback HTTP port |
| `STATUS_SUBDOMAIN_ROUTING`, `STATUS_BASE_DOMAIN` | Runner sets the server to `true` and `localhost` for hostname routing |
| `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` | Synthetic build-only value generated by the runner |

The supported runner constructs a fresh environment for PostgreSQL, the app and Vitest. It skips dotenv files and omits hosted credentials, PostgreSQL environment overrides and payment keys. The existing fixed TCP target `127.0.0.1:55432` remains available to legacy tooling in explicit integration mode. It is independent of `npm test`. Direct Vitest database tests fail closed without integration mode.

The full runner needs working System V shared memory and local process signaling for PostgreSQL startup and shutdown. The restrictive Mac desktop sandbox blocked fresh cluster initialization during SA-003. If a runner shows the same denial, use an authorized Cloud or CI execution environment for the clean-cluster check. Ordinary unit tests still run in the desktop sandbox.
